# Contributing to CareBridge

Keep changes focused on reliable, personalized communication. Avoid speculative infrastructure.

1. Open an issue before making substantial behavior changes.
2. Branch from `main` with a descriptive name.
3. Keep domain state separate from widgets, and preserve offline operation.
4. Add meaningful domain or widget tests.
5. Run formatting, analysis, tests, and relevant platform builds.
6. Open a pull request without generated build output or secrets.

Accessibility regressions are functional regressions. Check touch targets, contrast, semantics, text scaling, and phone and tablet layouts.

Do not add cloud services, tracking, authentication, medical claims, or copyrighted images without prior agreement.

Development commands, screenshot and icon regeneration, and documentation builds are described in the [contributing guide](https://quangshuynh.github.io/carebridge/contributing/).
